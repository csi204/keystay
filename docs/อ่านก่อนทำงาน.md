# ระบบบริหารจัดการภายในสำหรับโรงแรมขนาดเล็ก 5–10 ห้อง (Boutique Hotel / Poshtel)

## 🔐 สถาปัตยกรรมระบบล็อกอินจุดเดียวและการแบ่งสิทธิ์ (Unified Login & Role Redirection)

ระบบออกแบบหน้าจอเข้าสู่ระบบแบบ **"Single Portal for All Roles"** รวมศูนย์ไว้ที่หน้าจอเดียวที่ `/login` เพื่อความเรียบง่ายและปลอดภัยสูงสุด:

### 1. หน้าจอ `/login` จุดเดียว:
- พนักงานทุกบทบาท (Admin, Manager, Front Desk Cashier, Housekeeping) ล็อกอินผ่านหน้าต่าง `/login` เดียวกัน
- รองรับการกรอกข้อมูลด้วย **Email** หรือ **Username** พร้อม **Password**
- มี Checkbox **"จำฉันไว้ในระบบ" (Remember Me)**:
  - 🔘 **เมื่อติ๊กถูก (Checked):**
    - ระบบจะจดจำ Identifier (Email/Username) เก็บลง `localStorage` เพื่อให้เปิดมาครั้งต่อไปไม่ต้องพิมพ์ใหม่
    - ออก Refresh Token อายุยาว **30 วัน** บันทึกใน Persistent Storage เพื่อคงสถานะล็อกอินไว้อย่างปลอดภัย
  - ⚪ **เมื่อไม่ติ๊ก (Unchecked):**
    - ใช้งานโหมดชั่วคราว (Session Only) Token จะหมดอายุภายใน 24 ชั่วโมง หรือถูกล้างทิ้งเมื่อปิดเบราว์เซอร์ และไม่มีการจำรหัสผ่านหรือชื่อผู้ใช้

### 2. กระบวนการตรวจสอบและ Redirection:
1. เมื่อผู้ใช้ล็อกอินสำเร็จ `auth-user` จะออก JWT Token ที่มี Claims `role` (`admin` | `manager` | `front_desk` | `housekeeping`)
2. ฝั่ง Frontend Shell (`apps/web`) จะตรวจจับ Role และนำทาง (Redirect) ไปยังหน้าจอหลักของแต่ละแผนกอัตโนมัติ:
   - `admin` หรือ `manager` ➡️ Redirect ไปยัง **Manager & Admin Portal** (`/admin`)  
     > 💡 **ข้อตกลงเรื่อง UI:** ทั้ง `admin` และ `manager` ใช้หน้าจอเดียวกัน (`/admin`) แต่หากผู้ใช้ล็อกอินด้วย Role `manager` ระบบจะ **ซ่อนปุ่มแก้ไขสิทธิ์ (Role)** และ **ปุ่มลบผู้ใช้ (Delete User)** ออกไปตามนโยบายความปลอดภัย
   - `front_desk` ➡️ Redirect ไปยัง **Front Desk & Cashier Portal** (`/front-desk`)
   - `housekeeping` ➡️ Redirect ไปยัง **Housekeeping Portal** (`/housekeeping`)
3. **Security Guard:** หากผู้ใช้พยายามพิมพ์ URL ข้ามไปยัง Portal อื่นที่ตนเองไม่มีสิทธิ์ หรือพิมพ์ URL หน้าภายในโดยยังไม่ล็อกอิน Frontend Route Guard จะแสดงหน้า **404 Not Found** (Security by Obscurity) ทันที พร้อมปุ่มกดย้อนกลับไปหน้าที่แล้ว

## 📋 รายละเอียดเจาะลึก 100 APIs จำแนกตามเซอร์วิสและผู้รับผิดชอบ

### 🔐 Service #1: Auth/User Service (12 APIs) — ผู้รับผิดชอบ: เขต (`@hazeco`)
**ฐานข้อมูล D1:** `db_auth_user` | **Cache/Session:** Cloudflare KV (`keystay_kv`)  
*พัฒนาใน Phase 1 ([Issue #4](https://github.com/csi204/keystay/issues/4))*
1. `POST /register` — ลงทะเบียนผู้ใช้งานใหม่ (สร้างบัญชี Admin หรือพนักงาน)
2. `POST /login` — เข้าสู่ระบบ ตรวจสอบ bcrypt hash และออก JWT Access Token (15m) + Refresh Token (7d)
3. `POST /logout` — ออกจากระบบ ยกเลิก Session และ Revoke Token ใน KV
4. `POST /refresh-token` — ขอรับ Access Token ใหม่โดยใช้ Refresh Token
5. `GET /users` — ดึงรายชื่อผู้ใช้งานทั้งหมด (รองรับ filter ตาม role, is_active)
6. `GET /users/:id` — ดึงข้อมูลผู้ใช้งานรายบุคคล
7. `PUT /users/:id` — แก้ไขข้อมูลส่วนตัวผู้ใช้งาน (ชื่อ, นามสกุล, อีเมล)
8. `DELETE /users/:id` — ปิดการใช้งานผู้ใช้ (Soft Delete: `is_active = false`)
9. `PUT /users/:id/role` — เปลี่ยนบทบาทผู้ใช้ (4 Roles: `admin`, `manager`, `front_desk`, `housekeeping`)
10. `GET /users/:id/permissions` — ดูรายการสิทธิ์การเข้าถึงของผู้ใช้ตามบทบาท
11. `POST /forgot-password` — ขอกู้คืนรหัสผ่าน (สร้าง Password Reset Token)
12. `POST /reset-password` — ตั้งรหัสผ่านใหม่ด้วย Reset Token

### 🛏️ Service #2: Room Inventory Service (18 APIs) — ผู้รับผิดชอบ: บุญ (`@Legxcy77`)
**ฐานข้อมูล D1:** `db_room` | **Assets Storage:** Cloudflare R2 (`keystay`)  
*พัฒนาใน Phase 1 ([Issue #2](https://github.com/csi204/keystay/issues/2)) และ Phase 2 ([Issue #8](https://github.com/csi204/keystay/issues/8))*

14. `GET /rooms/:id` — ข้อมูลห้องพักรายห้องพร้อม Amenities

16. `PUT /rooms/:id` — แก้ไขรายละเอียดห้องพัก
17. `DELETE /rooms/:id` — ระงับการใช้งานห้องพัก (Soft delete: `is_active = false`)
18. `GET /rooms/:id/status` — ดึงสถานะปัจจุบันของห้องพัก (`available`, `reserved`, `occupied`, `checked_out`, `cleaning`, `maintenance`, `out_of_order`)

20. `GET /room-types` — รายการประเภทห้องพักทั้งหมด (Standard, Deluxe, Suite, Presidential)
21. `POST /room-types` — เพิ่มประเภทห้องพักใหม่
22. `PUT /room-types/:id` — แก้ไขประเภทห้องพักและอัตราค่าห้องฐาน (base_price)
23. `DELETE /room-types/:id` — ลบประเภทห้องพัก
24. `GET /rooms/available` — ค้นหาห้องว่างตามช่วงเวลาที่กำหนด
25. `GET /floors` — รายชื่อชั้นทั้งหมดในโรงแรม
26. `GET /floors/:id/rooms` — รายการห้องพักประจำแต่ละชั้น
27. `PUT /rooms/:id/maintenance` — ปรับห้องเข้าโหมดซ่อมบำรุง หรือปลดจากการซ่อมบำรุงกลับมาใช้งาน *(Phase 2)*
28. `GET /rooms/:id/history` — ดูประวัติการเปลี่ยนสถานะห้องย้อนหลัง
29. `POST /rooms/:id/amenities` — เพิ่มสิ่งอำนวยความสะดวกในห้องพัก (WiFi, Minibar, Bathtub)
30. `DELETE /rooms/:id/amenities/:amenityId` — ลบสิ่งอำนวยความสะดวกออกจากห้อง

42. `GET /reservations/today-checkins` — รายการที่ต้องเช็คอินวันนี้ (สำหรับ Front Desk Matrix) *(Phase 2)*
43. `GET /reservations/today-checkouts` — รายการที่ต้องเช็คเอาท์วันนี้ (สำหรับ Front Desk Matrix) *(Phase 2)*
44. `POST /guests` — บันทึกประวัติแขกใหม่ (ชื่อ, นามสกุล, เบอร์, อีเมล, บัตร ปชช./Passport)
45. `GET /guests` — รายชื่อแขกทั้งหมดในระบบ
46. `GET /guests/:id` — ข้อมูลแขกรายบุคคล
47. `PUT /guests/:id` — แก้ไขข้อมูลประวัติแขก
48. `DELETE /guests/:id` — ลบข้อมูลแขก
49. `POST /reservations/:id/extend-stay` — ขอขยายเวลาเข้าพัก (คำนวณคืนเพิ่ม) *(Phase 2)*
50. `POST /reservations/:id/upgrade-room` — ขออัปเกรดประเภทห้องพัก (คำนวณส่วนต่าง) *(Phase 2)*
51. `GET /reservations/calendar` — ข้อมูลตารางการจองแบบปฏิทิน (Timeline View)

53. `GET /reservations/:id/invoice-preview` — ดูตัวอย่างบิลล่วงหน้า *(Phase 2)*
54. `POST /reservations/:id/apply-discount` — ใช้โค้ดหรือบันทึกส่วนลดสำหรับการจอง *(Phase 2)*

## 🔄 สถาปัตยกรรม Asynchronous Event Bus (Upstash QStash)

ระบบใช้ **Upstash QStash** ในการกระจาย Event แบบ True 1:N Fan-out:
```
[Reservation Service]
        │
        ▼ (Check-out Event)
[Upstash QStash Topic: hotel.reservation.checkout]
   ├──> 1. [room-inventory]   -> ปรับสถานะห้องเป็น checked_out
   ├──> 2. [housekeeping]     -> สร้าง Task ทำความสะอาด (checkout_clean)
   ├──> 3. [billing]          -> สร้าง Bill รวบยอดค่าห้องและรอมินิบาร์
   └──> 4. [report-analytics] -> บันทึกสถิติ Occupancy และยอดเช็คเอาท์
```
เมื่อแม่บ้านทำความสะอาดเสร็จ:
```
[Housekeeping Service]
        │
        ▼ (Task Completed Event)
[Upstash QStash Topic: hotel.housekeeping.completed]
        │
        └──> [room-inventory] -> ปรับสถานะห้องกลับเป็น available พร้อมให้จองรอบต่อไป
```

## 🤝 จุดเชื่อมโยง Event สัญญา (Event Contracts)

ทุกทีมต้องอิมพอร์ต Zod Schemas และ TypeScript Types จาก `@keystay/events` (`packages/events/src/index.ts`) เพื่อรับ-ส่งข้อมูลระหว่าง Microservices ให้ตรงตามสัญญาทุกฟิลด์:

```typescript
// packages/events/src/index.ts
import { z } from 'zod';

// ========================================================
// 1. Check-in Event -> Upstash Topic: hotel.reservation.checkin
// ========================================================
export const ReservationCheckedInEventSchema = z.object({
  eventId: z.string().uuid(),
  eventType: z.literal('ReservationCheckedIn'),
  timestamp: z.string().datetime(),
  reservationId: z.string().uuid(),
  roomId: z.string().uuid(),
  roomNumber: z.string(),
  guestId: z.string().uuid(),
  guestName: z.string(),
  checkInTime: z.string().datetime(),
  expectedCheckOutDate: z.string(),
  performedBy: z.string().uuid(),
});
export type ReservationCheckedInEvent = z.infer<typeof ReservationCheckedInEventSchema>;

// ========================================================
// 2. Check-out Event -> Upstash Topic: hotel.reservation.checkout (Fan-out 4 ทาง)
// ========================================================
export const ReservationCheckedOutEventSchema = z.object({
  eventId: z.string().uuid(),
  eventType: z.literal('ReservationCheckedOut'),
  timestamp: z.string().datetime(),
  reservationId: z.string().uuid(),
  bookingNumber: z.string(),
  bookingType: z.enum(['standard', 'walk_in']),
  roomId: z.string().uuid(),
  roomNumber: z.string(),
  roomTypeId: z.string().uuid(),
  roomTypeName: z.string(),
  floor: z.string(),
  guestId: z.string().uuid(),
  guestName: z.string(),
  guestEmail: z.string().email().optional(),
  guestPhone: z.string().optional(),
  checkInDate: z.string(),
  actualCheckIn: z.string().datetime(),
  checkOutDate: z.string(),
  actualCheckOut: z.string().datetime(),
  totalNights: z.string(),
  nightlyRate: z.string(),
  roomTotalAmount: z.string(),
  depositAmount: z.string().default('0.00'), // ยอดมัดจำที่เก็บไว้ตอนเช็คอิน
  taxRate: z.string().default('0.07'),
  taxAmount: z.string(),
  netAmount: z.string(),
  currency: z.literal('THB').default('THB'),
  cleaningType: z.enum(['checkout_clean', 'deep_clean']).default('checkout_clean'),
  priority: z.enum(['normal', 'high', 'urgent']).default('normal'),
  specialNotes: z.string().optional(),
  performedBy: z.string().uuid(),
});
export type ReservationCheckedOutEvent = z.infer<typeof ReservationCheckedOutEventSchema>;

// ========================================================
// 3. Task Complete Event -> Upstash Topic: hotel.housekeeping.completed
// ========================================================
export const HousekeepingTaskCompletedEventSchema = z.object({
  eventId: z.string().uuid(),
  eventType: z.literal('HousekeepingTaskCompleted'),
  timestamp: z.string().datetime(),
  taskId: z.string().uuid(),
  roomId: z.string().uuid(),
  roomNumber: z.string(),
  staffId: z.string().uuid(),
  staffName: z.string(),
  completedAt: z.string().datetime(),
  inspectionStatus: z.enum(['passed', 'pending_inspection']).default('passed'),
  nextRoomStatus: z.literal('available'),
});
export type HousekeepingTaskCompletedEvent = z.infer<typeof HousekeepingTaskCompletedEventSchema>;

// ========================================================
// 4. Bill Paid Event -> Upstash Topic: hotel.billing.paid
// ========================================================
export const BillPaidEventSchema = z.object({
  eventId: z.string().uuid(),
  eventType: z.literal('BillPaid'),
  timestamp: z.string().datetime(),
  billId: z.string().uuid(),
  billNumber: z.string(),
  reservationId: z.string().uuid(),
  guestName: z.string(),
  roomNumber: z.string(),
  roomTypeName: z.string().optional(),
  subtotal: z.number(),
  taxAmount: z.number(),
  serviceCharge: z.number().default(0),
  discountAmount: z.number().default(0),
  totalAmount: z.number(),
  depositDeducted: z.number().default(0),
  amountPaid: z.number(),
  paymentMethod: z.string(),
  referenceNumber: z.string().optional(),
  performedBy: z.string().uuid().optional(),
});
export type BillPaidEvent = z.infer<typeof BillPaidEventSchema>;
```

### 🎯 หน้าที่ของแต่ละทีมในการรับ-ส่ง Event:
1. **เดียร์ (`reservation` & `billing`):**
   - เป็น **Producer** ยิง `ReservationCheckedIn` ไปที่ `hotel.reservation.checkin`
   - เป็น **Producer** ยิง `ReservationCheckedOut` ไปที่ `hotel.reservation.checkout`
   - เป็น **Producer** ยิง `BillPaid` ไปที่ `hotel.billing.paid`
   - ใช้ Transactional Outbox Pattern เขียนลงตาราง `outbox_events` พร้อมกับบันทึกการเช็คอิน/เอาท์
2. **บุญ (`room-inventory` & `housekeeping`):**
   - เป็น **Consumer** ที่ `POST /webhooks/checkout` ใน `room-inventory` เพื่อปรับสถานะห้องเป็น `checked_out`
   - เป็น **Consumer** ที่ `POST /webhooks/checkout` ใน `housekeeping` เพื่อสร้างภารกิจทำความสะอาดใหม่
   - เป็น **Producer** ยิง `HousekeepingTaskCompleted` เข้า Topic `hotel.housekeeping.completed` เมื่อตรวจงานผ่าน
   - เป็น **Consumer** ใน `room-inventory` รับ `hotel.housekeeping.completed` เพื่อปรับสถานะห้องกลับเป็น `available`
3. **เขต (`report-analytics`):**
   - เป็น **Consumer** ที่ `POST /webhooks/checkout` และ `POST /webhooks/bill-paid` เพื่อบันทึกสถิติ Occupancy, Daily Revenue, และ Room Performance ทันทีแบบ Event-driven
