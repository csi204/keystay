# แผนแบ่งงาน — Hotel Management System (3 สมาชิก 3 หน้าจอ 6 เซอร์วิส)

> อัปเดตล่าสุด: ปรับปรุงสถาปัตยกรรมตัด Role Billing แยกออก (รวมเข้า Front Desk Cashier), เปลี่ยนระบบ Event Fan-out มาใช้ **Upstash QStash (Serverless Pub/Sub via Webhooks)**, และแบ่ง Frontend ให้สมาชิก 3 คนดูแลคนละ 1 Portal ชัดเจน

---

| สมาชิก | Frontend Portal ที่รับผิดชอบ | ขอบเขตหน้าจอ | งานเสริม |
|---|---|---|---|

## ⚙️ Backend Services — มีทั้งหมด 7 เซอร์วิส (รวม Gateway)

| เซอร์วิส | หน้าที่หลัก | DB ที่เป็นเจ้าของ | เจ้าของ |
|---|---|---|---|
| `api-gateway` | จุดรับ Request เดียว, ตรวจ JWT, RBAC Middleware (4 Roles), Route ไปยัง Service | — (ไม่มี DB) | **เขต** |
| `auth-user` | Users, Sessions, Permissions (RBAC), Password Reset, ออก/Verify JWT | `db_auth_user` (D1) + KV | **เขต** |
| `report-analytics` | Daily Stats, Monthly Revenue Summary, Room Performance, Audit Event Log | `db_report` (D1) | **เขต** |
| `room-inventory` | Rooms, Room Types, Floors, Amenities, Real-time Room Status History | `db_room` (D1) | **บุญ** |
| `housekeeping` | Staff, Tasks (Checkout Clean, Deep Clean), Room Issues, Schedules | `db_housekeeping` (D1) | **บุญ** |
| `reservation` | Guests, Reservations, Booking History, Date Range Availability, Check-in/out | `db_reservation` (D1) | **เดียร์** |
| `billing` | Bills, Bill Items (Room + Minibar), Payments (Cash, Card, QR), Invoices | `db_billing` (D1) | **เดียร์** |

### เหตุผลในการแบ่ง Backend แบบ 2 เซอร์วิสต่อคน:
1. **เดียร์ (Front Office & Financial):** ดูแล `reservation` (24 APIs) + `billing` (16 APIs) = **40 APIs** เพราะทั้งสองส่วนนี้ผูกกันโดยตรงที่หน้าเคาน์เตอร์ (เช็คเอาท์เสร็จ คิดเงิน ออกบิล ทอนเงินมัดจำ) จบในมือเดียร์ ไม่ต้องรอข้ามคน
2. **บุญ (Room & Operations):** ดูแล `room-inventory` (18 APIs) + `housekeeping` (16 APIs) = **34 APIs** คุมวงจรสถานะห้องพัก (Room State Machine) และงานแม่บ้านเข้าด้วยกัน เมื่อแม่บ้านทำความสะอาดเสร็จ ปรับสถานะห้องเป็น `available` ได้อย่างราบรื่น
3. **เขต (Core Platform & Analytics):** ดูแล `api-gateway` + `auth-user` (12 APIs) + `report-analytics` (14 APIs) = **26 APIs + Core Infra** ดูแลกระดูกสันหลังระบบ ความปลอดภัย สิทธิ์ และระบบวิเคราะห์ข้อมูลผู้บริหาร

## 🔄 สถาปัตยกรรมข้อความ: Upstash QStash (Serverless Pub/Sub)

เดิมที Cloudflare Queues ไม่รองรับ 1:N Fan-out บนคิวเดียว (หากมี Consumer หลายตัวจะแย่งดึงข้อความกัน ทำให้บางเซอร์วิสไม่ได้รับข้อความ) ระบบจึงเปลี่ยนมาใช้ **Upstash QStash**:
- **ผู้ส่ง (Producer):** ยิง REST HTTP POST ครั้งเดียวเข้า Topic เช่น `https://qstash.upstash.io/v2/topics/hotel.reservation.checkout`
- **ผู้รับ (Subscribers):** QStash จะกระจายข้อความ (Fan-out) ยิง Webhook POST ไปยัง endpoint ของแต่ละเซอร์วิสพร้อมกัน:
  1. `room-inventory` (`POST /webhooks/checkout`) → ปรับห้องเป็น `checked_out`
  2. `housekeeping` (`POST /webhooks/checkout`) → สร้าง Task ทำความสะอาด (`checkout_clean`)
  3. `billing` (`POST /webhooks/checkout`) → สร้าง Bill สรุปค่าห้องและรอรวมยอดมินิบาร์
  4. `report-analytics` (`POST /webhooks/checkout`) → บันทึกสถิติ checkout ประจำวัน
- **ข้อดี:** ทำงานผ่าน HTTP 100%, มี Retry แบบ Exponential Backoff, มี Dead-Letter Queue (DLQ), และทดสอบใน Local Dev ได้ง่ายมาก

## 🤝 จุดเชื่อมโยง Event สัญญา (Event Contracts)

```typescript
// packages/events/src/reservation-events.ts
// ทุกคน import schema นี้จาก packages/events
import { z } from 'zod';

// 1. Check-in Event -> ส่งเข้า Upstash Topic: hotel.reservation.checkin
export const ReservationCheckedInEventSchema = z.object({
  eventId: z.string().uuid(),
  eventType: z.literal('ReservationCheckedIn'),
  timestamp: z.string().datetime(),
  reservationId: z.string().uuid(),
  roomId: z.string().uuid(),
  roomNumber: z.string(),
  guestId: z.string().uuid(),
  guestName: z.string(),
  checkInTime: z.string().datetime(),
  expectedCheckOutDate: z.string(),
  performedBy: z.string().uuid(),
});

// 2. Check-out Event -> ส่งเข้า Upstash Topic: hotel.reservation.checkout (Fan-out 4 ทาง)
export const ReservationCheckedOutEventSchema = z.object({
  eventId: z.string().uuid(),
  eventType: z.literal('ReservationCheckedOut'),
  timestamp: z.string().datetime(),
  reservationId: z.string().uuid(),
  bookingNumber: z.string(),
  bookingType: z.enum(['standard', 'walk_in']),
  roomId: z.string().uuid(),
  roomNumber: z.string(),
  roomTypeId: z.string().uuid(),
  roomTypeName: z.string(),
  floor: z.string(),
  guestId: z.string().uuid(),
  guestName: z.string(),
  guestEmail: z.string().email().optional(),
  guestPhone: z.string().optional(),
  checkInDate: z.string(),
  actualCheckIn: z.string().datetime(),
  checkOutDate: z.string(),
  actualCheckOut: z.string().datetime(),
  totalNights: z.string(),
  nightlyRate: z.string(),
  roomTotalAmount: z.string(),
  depositAmount: z.string().default('0.00'), // ยอดมัดจำที่เก็บไว้ตอนเช็คอิน
  taxRate: z.string().default('0.07'),
  taxAmount: z.string(),
  netAmount: z.string(),
  currency: z.literal('THB').default('THB'),
  cleaningType: z.enum(['checkout_clean', 'deep_clean']).default('checkout_clean'),
  priority: z.enum(['normal', 'high', 'urgent']).default('normal'),
  specialNotes: z.string().optional(),
  performedBy: z.string().uuid(),
});

// 3. Task Complete Event -> ส่งเข้า Upstash Topic: hotel.housekeeping.completed
export const HousekeepingTaskCompletedEventSchema = z.object({
  eventId: z.string().uuid(),
  eventType: z.literal('HousekeepingTaskCompleted'),
  timestamp: z.string().datetime(),
  taskId: z.string().uuid(),
  roomId: z.string().uuid(),
  roomNumber: z.string(),
  staffId: z.string().uuid(),
  staffName: z.string(),
  completedAt: z.string().datetime(),
  inspectionStatus: z.enum(['passed', 'pending_inspection']).default('passed'),
  nextRoomStatus: z.literal('available'),
});
```

## 📅 แผนการพัฒนาตามลำดับ (Phases)

### Phase 0 — เขตทำคนเดียวก่อน (Foundational Infrastructure)
1. Setup pnpm monorepo + `packages/types`, `packages/events`, `packages/config`
2. Setup GitHub repo + branch protection บน `main` และ `dev`
3. Setup Cloudflare account + สร้าง D1 ทั้ง 6 ก้อน + KV namespace
4. Setup **Upstash QStash account** + สร้าง Topics ที่ต้องใช้
5. เตรียม `.dev.vars` และสคริปต์ `pnpm dev` ให้เพื่อนรันได้ทันที

### Phase 1 — Foundational Core Services (3 คนขนานกัน)
- **เขต:** `auth-user` (CRUD Users, Login/Logout, JWT, RBAC) + `api-gateway` (CORS, Rate Limit, Auth Guard)
- **บุญ:** `room-inventory` (D1 schema, CRUD rooms, types, floors, Real-time status)
- **เดียร์:** `reservation` (D1 schema, CRUD guests, Advance Booking Date Range check)

> ⚠️ `auth-user` ของเขตต้องพร้อมก่อน เพื่อให้เดียร์และบุญใช้ Token ในการทดสอบ API

### Phase 2 — Transactions & Pub/Sub Integration
- **เดียร์:** เพิ่ม Check-in, Check-out บน `reservation`, เชื่อม `billing` สร้างบิลและรับชำระเงิน, ใส่ Outbox `db.batch()` ส่งเข้า QStash
- **บุญ:** ทำ `housekeeping` (Tasks, Staff, Issues), ทำ Webhook Endpoint รับ Event Checkout เพื่อสร้างงาน และส่ง Event คืนห้องเมื่อทำความสะอาดเสร็จ
- **เขต:** เพิ่ม `report-analytics` รับ Event สรุปรายได้และ Occupancy, เริ่มต้นโครงร่าง Frontend Shell

### Phase 3 — Frontend Integration (3 คน 3 จอ)
- **เดียร์:** พัฒนา **Front Desk & Cashier Portal** (Room Matrix, Check-in/out Modal, Cashier Bill Settlement, Minibar add, Print Invoice)
- **บุญ:** พัฒนา **Housekeeping Portal** (Kanban Board, รับงาน, บันทึกตรวจห้อง, แจ้งห้องชำรุด)
- **เขต:** พัฒนา **Manager & Admin Portal** (Dashboard สถิติ, User Management, Export Reports)

### Phase 4 — E2E Testing & Acceptance (UAT)
- รัน UAT 21 Test Cases ใน `docs/uat.md` ร่วมกันทั้ง 3 คน
- ทดสอบกรณี Network หลุด, Event ซ้ำซ้อน (Idempotency), และข้อผิดพลาดใน Dead-Letter Queue (DLQ)
- เตรียมข้อมูล Mock Data และ Demo Script สำหรับนำเสนอ
