## 🔐 สถาปัตยกรรมระบบล็อกอินจุดเดียวและการแบ่งสิทธิ์ (Unified Login & Role Redirection)

ระบบออกแบบหน้าจอเข้าสู่ระบบแบบ **"Single Portal for All Roles"** รวมศูนย์ไว้ที่หน้าจอเดียวที่ `/login` เพื่อความเรียบง่ายและปลอดภัยสูงสุด:

### 1. หน้าจอ `/login` จุดเดียว:
- พนักงานทุกบทบาท (Admin, Manager, Front Desk Cashier, Housekeeping) ล็อกอินผ่านหน้าต่าง `/login` เดียวกัน
- รองรับการกรอกข้อมูลด้วย **Email** หรือ **Username** พร้อม **Password**
- มี Checkbox **"จำฉันไว้ในระบบ" (Remember Me)**:
  - 🔘 **เมื่อติ๊กถูก (Checked):**
    - ระบบจะจดจำ Identifier (Email/Username) เก็บลง `localStorage` เพื่อให้เปิดมาครั้งต่อไปไม่ต้องพิมพ์ใหม่
    - ออก Refresh Token อายุยาว **30 วัน** บันทึกใน Persistent Storage เพื่อคงสถานะล็อกอินไว้อย่างปลอดภัย
  - ⚪ **เมื่อไม่ติ๊ก (Unchecked):**
    - ใช้งานโหมดชั่วคราว (Session Only) Token จะหมดอายุภายใน 24 ชั่วโมง หรือถูกล้างทิ้งเมื่อปิดเบราว์เซอร์ และไม่มีการจำรหัสผ่านหรือชื่อผู้ใช้

### 2. กระบวนการตรวจสอบและ Redirection:
1. เมื่อผู้ใช้ล็อกอินสำเร็จ `auth-user` จะออก JWT Token ที่มี Claims `role` (`admin` | `manager` | `front_desk` | `housekeeping`)
2. ฝั่ง Frontend Shell (`apps/web`) จะตรวจจับ Role และนำทาง (Redirect) ไปยังหน้าจอหลักของแต่ละแผนกอัตโนมัติ:
   - `admin` หรือ `manager` ➡️ Redirect ไปยัง **Manager & Admin Portal** (`/admin`)
   - `front_desk` ➡️ Redirect ไปยัง **Front Desk & Cashier Portal** (`/front-desk`)
   - `housekeeping` ➡️ Redirect ไปยัง **Housekeeping Portal** (`/housekeeping`)
3. **Security Guard:** หากผู้ใช้พยายามพิมพ์ URL ข้ามไปยัง Portal อื่นที่ตนเองไม่มีสิทธิ์ Frontend Route Guard และ API Gateway RBAC Middleware จะสั่งปฏิเสธ (403 Forbidden) ทันที

## 📋 รายละเอียดเจาะลึก 100 APIs จำแนกตามเซอร์วิสและผู้รับผิดชอบ

### 🔐 Service #1: Auth/User Service (12 APIs) — ผู้รับผิดชอบ: เขต (`@hazeco`)
**ฐานข้อมูล D1:** `db_auth_user` | **Cache/Session:** Cloudflare KV (`keystay_kv`)  
*พัฒนาใน Phase 1 ([Issue #4](https://github.com/csi204/keystay/issues/4))*
1. `POST /register` — ลงทะเบียนผู้ใช้งานใหม่ (สร้างบัญชี Admin หรือพนักงาน)
2. `POST /login` — เข้าสู่ระบบ ตรวจสอบ bcrypt hash และออก JWT Access Token (15m) + Refresh Token (7d)
3. `POST /logout` — ออกจากระบบ ยกเลิก Session และ Revoke Token ใน KV
4. `POST /refresh-token` — ขอรับ Access Token ใหม่โดยใช้ Refresh Token
5. `GET /users` — ดึงรายชื่อผู้ใช้งานทั้งหมด (รองรับ filter ตาม role, is_active)
6. `GET /users/:id` — ดึงข้อมูลผู้ใช้งานรายบุคคล
7. `PUT /users/:id` — แก้ไขข้อมูลส่วนตัวผู้ใช้งาน (ชื่อ, นามสกุล, อีเมล)
8. `DELETE /users/:id` — ปิดการใช้งานผู้ใช้ (Soft Delete: `is_active = false`)
9. `PUT /users/:id/role` — เปลี่ยนบทบาทผู้ใช้ (4 Roles: `admin`, `manager`, `front_desk`, `housekeeping`)
10. `GET /users/:id/permissions` — ดูรายการสิทธิ์การเข้าถึงของผู้ใช้ตามบทบาท
11. `POST /forgot-password` — ขอกู้คืนรหัสผ่าน (สร้าง Password Reset Token)
12. `POST /reset-password` — ตั้งรหัสผ่านใหม่ด้วย Reset Token

### 🛏️ Service #2: Room Inventory Service (18 APIs) — ผู้รับผิดชอบ: บุญ (`@Legxcy77`)

23. `DELETE /room-types/:id` — ลบประเภทห้องพัก
24. `GET /rooms/available` — ค้นหาห้องว่างตามช่วงเวลาที่กำหนด
25. `GET /floors` — รายชื่อชั้นทั้งหมดในโรงแรม
26. `GET /floors/:id/rooms` — รายการห้องพักประจำแต่ละชั้น
27. `PUT /rooms/:id/maintenance` — ปรับห้องเข้าโหมดซ่อมบำรุง หรือปลดจากการซ่อมบำรุงกลับมาใช้งาน *(Phase 2)*
28. `GET /rooms/:id/history` — ดูประวัติการเปลี่ยนสถานะห้องย้อนหลัง
29. `POST /rooms/:id/amenities` — เพิ่มสิ่งอำนวยความสะดวกในห้องพัก (WiFi, Minibar, Bathtub)
30. `DELETE /rooms/:id/amenities/:amenityId` — ลบสิ่งอำนวยความสะดวกออกจากห้อง

## 🔄 สถาปัตยกรรม Asynchronous Event Bus (Upstash QStash)

ระบบใช้ **Upstash QStash** ในการกระจาย Event แบบ True 1:N Fan-out:
```
[Reservation Service]
        │
        ▼ (Check-out Event)
[Upstash QStash Topic: hotel.reservation.checkout]
   ├──> 1. [room-inventory]   -> ปรับสถานะห้องเป็น checked_out
   ├──> 2. [housekeeping]     -> สร้าง Task ทำความสะอาด (checkout_clean)
   ├──> 3. [billing]          -> สร้าง Bill รวบยอดค่าห้องและรอมินิบาร์
   └──> 4. [report-analytics] -> บันทึกสถิติ Occupancy และยอดเช็คเอาท์
```
เมื่อแม่บ้านทำความสะอาดเสร็จ:
```
[Housekeeping Service]
        │
        ▼ (Task Completed Event)
[Upstash QStash Topic: hotel.housekeeping.completed]
        │
        └──> [room-inventory] -> ปรับสถานะห้องกลับเป็น available พร้อมให้จองรอบต่อไป
```

## 🛠️ คู่มือการรันระบบในเครื่อง (Local Development)

```bash
# 1. ติดตั้ง Dependencies ทั้งหมด
pnpm install

# 2. รันระบบทั้งหมดในโหมดจำลอง Local (ข้อมูลจำลองอยู่ในเครื่อง ไม่กระทบ Cloudflare ของจริง)
pnpm dev

# 3. รันเฉพาะเซอร์วิสที่ตนเองรับผิดชอบ (ตัวอย่าง)
pnpm --filter @keystay/room-inventory dev
pnpm --filter @keystay/reservation dev
pnpm --filter @keystay/web dev
```

> 💡 **หมายเหตุสำคัญ:** รายละเอียดการทำงานของ Local Mode เทียบกับ Remote Mode สามารถอ่านเพิ่มเติมได้ใน [RUNNING_LOCALLY.md](file:///d:/code/keystay/docs/RUNNING_LOCALLY.md)
